# Security Policy

Shapy ships two packages:

- `shapy-bg` — a browser-only, zero-dependency Web Component that renders seedable
  generative backgrounds.
- `shapy-render` — an optional Node.js export package that captures Shapy frames
  with Playwright and encodes them with ffmpeg.

Every attribute, registry value, color, image URL, text value, and render option
is treated as untrusted input.

## Supported versions

| Package | Version | Supported |
| --- | --- | --- |
| `shapy-bg` | `1.0.x` | Yes |
| `shapy-bg` | `< 1.0` | No |
| `shapy-render` | `1.0.x` | Yes |
| `shapy-render` | `< 1.0` | No |

Security fixes are released as patch versions on the current major line for both
packages.

## Reporting a vulnerability

**Do not open a public issue for a security problem.**

Use GitHub's private vulnerability reporting:

<https://github.com/hemant-rao/shapy-bg/security/advisories/new>

Include:

- the affected package and version or commit,
- a minimal reproduction,
- the browser or Node.js/operating system environment,
- the impact you believe the issue has,
- any suggested fix or mitigation.

You will receive an acknowledgement as soon as possible, usually within a few
days. Please give the maintainer time to investigate and release a fix before
disclosing the issue publicly.

## Security model

### Core package (`shapy-bg`)

- **No runtime dependencies.** The published package has no third-party runtime
  code.
- **No `eval` or `new Function`.** Renderer script text is static and generated
  from `packages/shapy-bg/src/shapy-index.html`.
- **Shadow DOM isolation.** The renderer lives in an open shadow root. Host CSS
  cannot style its internals; use the documented `::part()` hooks and
  `--shapy-*` variables.
- **Registry data is per-instance.** Custom groups arrive through the
  `registry-data` attribute and are never stored on `globalThis`.
- **Image URLs are validated.** Only `http(s)`, protocol-relative, relative, and
  safe `data:image/*` URLs are accepted. `javascript:`, `data:text/html`,
  `blob:`, `ftp:`, other schemes, and URLs containing backslashes are dropped.
- **Icons are path data.** Raw SVG markup is rejected; path data is validated
  against an allowlist of SVG path commands and numbers.
- **Colors are validated.** Color attributes and `custom-colors` are checked
  against a CSS color allowlist and the browser's color parser.
- **Text is plain text.** The overlay creates text nodes. HTML in `text`,
  `text-accent`, `subtext`, or `eyebrow` is displayed, never executed.
- **Remote images are not fetched by Shapy.** The browser loads allowed image
  URLs directly; Shapy does not proxy or inspect remote content.

### Export package (`shapy-render`)

- **Loopback-only capture server.** The package starts a local HTTP server on
  `127.0.0.1` on an ephemeral port. It serves only the installed `shapy-bg` package
  files, and resolved paths must stay inside the package directory, so path
  traversal requests are rejected. Nothing is exposed on a remote interface.
- **No user HTML.** The capture page is generated by `shapy-render`. Render
  options are passed to the element through the same validated `setOptions()`
  path used by the core package.
- **Headless browser isolation.** Frames are captured in a Playwright-managed
  headless Chromium context with a fixed viewport, color profile, and device
  pixel ratio.
- **Local output paths.** Output, poster, and PNG-sequence paths are supplied by
  the caller and written as local files. Temporary frame directories live in the
  operating system temp directory and are removed unless `keepFrames` is used.
- **External ffmpeg boundary.** `shapy-render` resolves ffmpeg from `--ffmpeg`,
  `SHAPY_FFMPEG`, `PATH`, or Playwright's bundled build and runs it as a local
  executable. Only trusted local ffmpeg binaries should be supplied. Shapy does
  not download or execute ffmpeg itself.
- **Dependency monitoring.** Playwright is the only runtime dependency; Chromium
  is installed separately. CI runs `npm audit` and Dependabot opens weekly
  dependency update pull requests.

## Scope

In scope:

- the `shapy-bg` package source and published tarball,
- the custom element, renderer, sanitization, and public API,
- the `shapy-render` package source and published tarball, including the CLI,
  capture server, input validation, and encoding pipeline,
- the repository demos when the issue is caused by package code.

Out of scope:

- vulnerabilities in the demo's development dependencies,
- browser bugs, Chromium/Playwright internals, or system ffmpeg bugs that cannot
  be triggered through Shapy's documented API,
- user-supplied ffmpeg binaries or other local executables,
- social engineering,
- issues that require an already-compromised page or extension.

## Safe harbor

Good-faith security research is welcome. Do not access, modify, or exfiltrate
data that does not belong to you, and do not run denial-of-service tests against
public infrastructure.
